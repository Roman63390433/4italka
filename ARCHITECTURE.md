# Архитектура «Читалки»

Читалка — PWA: обычный сайт из HTML, CSS и JavaScript, который Chrome на Android ставит на главный экран. Сервера нет, всё хранится в телефоне. Сборки нет: файлы открываются браузером как есть. Чужих библиотек тоже нет — даже zip распаковывается встроенными средствами браузера.

## Части и связи

```
 Экран (index.html + css/style.css)
   │  нажатия
 ┌─▼──────────── ИНТЕРФЕЙС ─────────────┐
 │ app.js        — запуск, нижнее меню, экран «Ещё» (стиль, место в памяти)
 │ shelf.js      — полка: список, добавление, удаление, поиск
 │ reader-ui.js  — экран чтения: касания, меню, оглавление, сноски
 │ look.js       — оформление: применяет настройки и рисует их переключатели
 │ sheet.js      — панели снизу, вопросы, подсказки (вместо alert/confirm) и кнопка «назад» Android
 └─┬───────────────────────────────────┘
   │ вызывает
 ┌─▼──────────── ЛОГИКА (без кнопок) ───┐
 │ parsers/index.js — определяет формат и зовёт нужный разборщик
 │ parsers/fb2.js   — fb2 → главы, обложка, сноски
 │ parsers/epub.js  — epub → главы, обложка
 │ zip.js           — распаковка zip (epub и fb2.zip)
 │ sanitize.js      — чистит HTML книги: пропускает только безопасные теги
 │ paginator.js     — режет главу на страницы, считает прогресс
 │ settings.js      — настройки по умолчанию и их сохранение
 └─┬───────────────────────────────────┘
   │ читает и пишет
 ┌─▼──────────── ХРАНИЛИЩЕ ─────────────┐
 │ storage.js: IndexedDB «chitalka» — books (название, автор, обложка, размер),
 │             files (сам файл книги); localStorage — настройки и место чтения
 └──────────────────────────────────────┘
 sw.js + manifest.json — значок на экране и работа без интернета
```

Правило: файлы логики ничего не знают про кнопки и экраны. Интерфейс вызывает логику, а не наоборот.

## Путь данных

1. **Добавление.** «+» → системный выбор файла → `shelf.js` → `parsers` достаёт название, автора, обложку и объём текста → `storage.addBook` кладёт карточку в `books`, а файл в `files` → полка перерисовывается.
2. **Открытие.** Нажатие на книгу → `storage.getFile` → `parsers` строит главы (HTML уже очищен) → `paginator` показывает нужную главу и страницу из сохранённой позиции.
3. **Листание.** Касание или свайп → `paginator.next/prev` → позиция `{глава, доля главы}` пишется в localStorage. Доля, а не номер страницы, — чтобы после смены шрифта открыть то же место.
4. **Настройки.** Панель оформления → `settings.save` → переменные CSS меняются → `paginator` заново раскладывает текст и остаётся на том же месте.

## Как считаются страницы

Глава выводится в CSS-колонки шириной в экран. Одна колонка — одна страница, листание сдвигает текст на ширину экрана. Страницы в текущей главе считаются точно. Общее число («18 из 662») оценивается по числу букв: буквы всей книги делятся на число букв на одной странице текущей главы.

## Формат хранения

- `books`: `{ id, title, author, format, size, chars, cover: Blob|null, added, opened }`
- `files`: `{ id, blob }`
- localStorage `chitalka.settings`: `{ style, page, font, size, lh, margin, dim }`
- localStorage `chitalka.pos.<id>`: `{ ch, frac, percent, at }`

## Безопасность

Книга — чужой файл, в нём может быть вредный код. `sanitize.js` пересобирает текст из короткого списка тегов (абзацы, заголовки, курсив, картинки, таблицы…) без атрибутов. Скрипты, стили и ссылки наружу отбрасываются, а картинки берутся только из самой книги.

## Файлы вне приложения

- `tools/ornaments.mjs` — рисует завитки и вписывает их в конец `css/style.css`.
- `tools/make-test-books.mjs` — делает тестовые книги в `test/` (fb2 в windows-1251, fb2.zip, epub с «вредным» кодом для проверки очистки).
